Verandert elk aangepast blok of meubel in een opslagcontainer. Er zijn drie modi beschikbaar.

| Type       | Gedrag                                                                          |
|------------|---------------------------------------------------------------------------------|
| `STORAGE`  | Gedeelde container - alle spelers zien dezelfde inventaris                      |
| `SHULKER`  | Inhoud reist mee in het item bij afbreken en wordt hersteld bij herplaatsen     |
| `DISPOSAL` | Prullenbak - inhoud wordt stilzwijgend verwijderd wanneer de GUI wordt gesloten |

Gebruik voor `name` een waarde uit [Sounds.json](https://minecraft.wiki/w/Sounds.json/Java_Edition_values) of een aangepast geluid met `namespace:value`.

Ondersteunt [MiniMessage](https://docs.papermc.io/adventure/minimessage/format/)-opmaak, [PlaceholderAPI](https://modrinth.com/plugin/placeholderapi)-placeholders en [ItemsAdder](https://itemsadder.com/)-lettertypeafbeeldingen.

## Inventaristype

Standaard opent opslag een kistachtige inventaris waarvan de hoogte wordt bepaald door `rows` (1-6, standaard: 3).
Stel `inventory_type` in om een inventaris van een specifiek type te openen - `rows` wordt genegeerd als dit is ingesteld.

| Waarde          | GUI-vorm                                    |
|-----------------|---------------------------------------------|
| `furnace`       | Oven (invoer + brandstof + uitvoer)         |
| `blast_furnace` | Hoogoven                                    |
| `smoker`        | Roker                                       |
| `brewing_stand` | Brouwstandaard (3 flesjes + 2 vakjes)       |
| `dispenser`     | Verdeler (3×3)                              |
| `dropper`       | Dropper (3×3)                               |
| `hopper`        | Trechter (1×5)                              |

```yaml
behaviours:
  storage:
    type: STORAGE
    inventory_type: furnace
    title: "<gray>Aangepaste Oven</gray>"
```

## Itembeperkingen

Vanaf versie 1.0.14 kan opslag beperken welke items spelers mogen invoegen. Gebruik `allowed_items` om alleen
overeenkomende items toe te staan:

```yaml
behaviours:
  storage:
    type: STORAGE
    allowed_items:
      - minecraft:book
      - "#minecraft:logs"
      - "#my_pack:building_materials"
```

Of gebruik `denied_items` om overeenkomende items te weigeren en alle andere items toe te staan:

```yaml
behaviours:
  storage:
    type: STORAGE
    denied_items:
      - minecraft:tnt
      - "#my_pack:portable_storage"
```

Vermeldingen mogen vanilla- of ItemsAdder-item-ID's, Minecraft-itemtags of aangepaste IAA-itemtags zijn.

<Callout type="warn">
    `allowed_items` en `denied_items` sluiten elkaar uit. Als beide zijn ingesteld, wordt het opslaggedrag afgewezen.
</Callout>

Een lege lijst `allowed_items` staat niets toe. Een lege lijst `denied_items` weigert niets. Als beide opties ontbreken,
blijft de opslag onbeperkt. De beperkingen gelden alleen voor nieuwe invoegingen door spelers; eerder opgeslagen inhoud
wordt niet verwijderd.

## Open variant

Je kunt optioneel `open_variant` instellen om het aangepaste blok, meubel of complexe meubel te laten veranderen naar een andere variant terwijl ten minste een speler de opslag open heeft.

Dit is handig voor dingen zoals:

- kisten die visueel openen
- vaten met een geopend model
- containers met een andere actieve toestand

```yaml
behaviours:
  storage:
    type: STORAGE
    open_variant: my_open_storage
```

`open_variant` moet de ID zijn van een ander aangepast blok, meubel of complex meubel, met gebruik van:
- `id`
- `namespace:id`

Zie [ID's](/nl/docs/compatibility/ids) voor ID-syntax.

Wanneer de inventaris door alle spelers wordt gesloten, keert de storage terug naar zijn normale variant.

<Callout>
    `open_variant`-waarden voor complex furniture worden ondersteund vanaf ItemsAdderAdditions 1.0.12. Block-storage moet een blockvariant gebruiken; furniture en complex furniture kunnen furniture, complex furniture of een item display-model gebruiken.
</Callout>

## Inhoudsvarianten

Vanaf versie 1.0.13 kan een gesloten opslaghouder van uiterlijk veranderen op basis van hoe vol deze is.

```yaml
behaviours:
  storage:
    type: STORAGE
    empty_variant: my_empty_storage   # optioneel; lege inventaris
    filled_variant: my_filled_storage # optioneel; elke niet-lege inventaris
    half_variant: my_half_storage     # optioneel; gedeeltelijk gevulde inventaris
    full_variant: my_full_storage     # optioneel; elk slot gevuld tot de stapellimiet
```

`filled_variant` is de eenvoudige optie met twee toestanden: deze wordt voor elke niet-lege inventaris gebruikt, tenzij
een specifiekere `half_variant` of `full_variant` is ingesteld. Ontbrekende varianten vallen terug op `filled_variant`
en daarna op het oorspronkelijke uiterlijk van de opslaghouder.

`open_variant` heeft voorrang zolang spelers de inventaris bekijken. Nadat de laatste speler deze sluit, wordt de juiste
inhoudsvariant hersteld. ID's en blok-/furniturecompatibiliteit volgen dezelfde regels als `open_variant`, en de rotatie
van directionele blokken blijft behouden.
